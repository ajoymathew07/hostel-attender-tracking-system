Settings

These take effect on the next complaint to arrive — nothing is redeployed and nothing is restarted. A field left at its original value is not stored at all, so it keeps following the application's own default if that ever changes.

Who gets the work

An attender's score is floor weight × floor proximity + load weight × free capacity. The two weights must add up to 1, so each reads as the share of the decision it carries.

Higher sends work to whoever covers the floor.

Higher spreads work away from whoever is busiest.

Weighted tasks (P1 counts 3, P2 counts 2, P3 counts 1) at which an attender counts as full. Above it everyone still gets work — you are told the queue is saturated.

Floor proximity itself is fixed, because only the order of its values means anything: the floor itself scores 1.0 as primary and 0.7 as secondary, an adjacent floor 0.4, and each further floor 0.05 less, never below 0.1.

What counts as late

Hours of working time from the moment the resident pressed submit. A complaint that arrives at 23:00 does not burn its window overnight. Past 1.5× the window the priority escalates a step, capped at P1.
